# v0.9.0 "Scale to 100k" — Release Notes

> The parent agent merges this into CHANGELOG.md. Do not duplicate there.

## What changed

QuotePilot is now architecturally ready for 100k monthly active users and
hundreds of concurrent quote submissions. Every new piece of infrastructure
is **optional with a graceful in-memory fallback** — `scripts/dev.sh` works
from a clean checkout with zero new config.

### Queue abstraction (`apps/api/src/services/queue.ts`)

- New `JobQueue` interface (`enqueue`, `getJob`, `onComplete`,
  `requestNotifyOnComplete`, `close`).
- `MemoryQueue` (default): the original v0.2.0 behavior, unchanged —
  single process, jobs lost on restart.
- `BullMQQueue`: selected when `REDIS_URL` is set. Job state in Redis hashes
  (24h TTL), worker concurrency 10, attempts 2 with exponential backoff.
  Any fleet instance can serve `GET /api/quotes/:jobId`; jobs survive restarts.
- Shared execution core (`jobExecutor.ts`) so both backends run byte-identical
  fan-out, ranking, analytics, and email logic.

### Quote-result cache (`apps/api/src/services/quoteCache.ts`)

- Completed results cached under SHA-256 of **rating factors only**
  (state, ZIP, driver risk fields, vehicle fields, coverage) — email, phone,
  and names never touch the key.
- Redis when `REDIS_URL` set, else in-memory LRU (500 entries). TTL from
  `CACHE_TTL_SECONDS` (default 3600).
- `POST /api/quote` returns `200 + cached:true` with inline results on a hit
  (~10ms); `202 + cached:false` on a miss. `QuoteJob.cached` added to the
  shared type.

### Analytics sink (`apps/api/src/services/analyticsSink.ts`)

- `AnalyticsSink` interface; `SqliteSink` (default, original behavior) and
  `PostgresSink` via `pg` when `DATABASE_URL` is set (schema-compatible).
- Fail-open: Postgres connection failure warns loudly and falls back to
  SQLite — analytics never breaks quoting. `track()` stays non-blocking.
- `analyticsService.ts` keeps its export surface (`track`, `summary`,
  `hashSession`, `getDb`, `_resetDb`).

### Rate limiting (`apps/api/src/middleware/rateLimit.ts`)

- Store factory: `rate-limit-redis` when `REDIS_URL` set, else the in-memory
  default. Correct per-IP limits across a fleet; fail-open with a warning.
- Tiers are env-configurable: `RATE_LIMIT_GLOBAL_PER_MIN` (300),
  `RATE_LIMIT_QUOTE_PER_MIN` (10), `RATE_LIMIT_ANALYTICS_EVENT_PER_MIN` (120).

### Statelessness

- Places agent cache → shared Redis cache when `REDIS_URL` set, else the
  same per-instance Map (24h TTL; staleness tolerable for business listings).
- `/api/health` now reports live backend selection
  (`queue`, `analytics`, `cache`, `rateLimitStore`).
- Graceful shutdown (`index.ts`): SIGTERM/SIGINT → stop accepting → 15s
  drain → close queue and sink.

### Load test (`apps/api/tests/load/quote-spike.js`)

- k6: ramp 0→200 VUs, hold 200 for 2 min, ramp down. Thresholds:
  `http_req_failed < 1%`, `quote_submit p95 < 2s`, `quote_complete p95 < 12s`.
- Small-pass result (20 VUs / 75s, in-memory stack): **2,205 iterations,
  0 failed, submit p95 3.7ms, 99.8% cache hits.**

### Docs

- `docs/SCALING.md`: architecture diagram, before/after bottleneck table,
  100k-MAU capacity math, env var reference, horizontal-scaling runbook,
  explicit not-built list.
- `apps/api/UPGRADE_PATH.md`: marked implemented by v0.9.0.

## Verification

- `scripts/build.sh` green (API + shared).
- API suite: **133/138 pass**. The 5 failures are pre-existing
  `web compliance surfaces (static)` tests that `readFileSync` Vite-era web
  files (`apps/web/src/components/Layout.tsx`) deleted by the concurrent
  Next.js migration — unrelated to this release, owned by that track.
- 16 new `scaling.test.ts` tests pass (queue parity, cache hit/miss/TTL/LRU,
  PII-free keys, sink selection + fail-open, rate-limit factory, HTTP
  cached flow).
- Live smoke: API boots with zero config; quote flow 202 → live progress →
  complete (6 results); repeat request 200 + `cached:true` in 13ms.
- k6 small pass: 2,205 iterations, 0 failures, all thresholds green.

## Deferred (with reasons)

- **BullMQ e2e test**: needs a live Redis; not available in CI. Factory
  selection + fail-open paths are tested; Redis impls degrade loudly.
- **Separate worker deployment**: worker runs in-process (concurrency 10);
  split when load justifies.
- **Per-carrier child jobs / DLQ / email queue**: justified when real carrier
  APIs arrive, not for simulated adapters.
- **Full 200-VU k6 run**: script delivered with thresholds; run against a
  staged deploy with relaxed `RATE_LIMIT_*` vars.
