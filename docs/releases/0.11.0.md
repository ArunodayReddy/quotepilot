# v0.11.0 "Real quotes" — Release Notes

> The parent agent merges this into CHANGELOG.md. Do not duplicate there.

**Date:** 2026-10-08
**Type:** feature — agent-mediated real-quote flow

## The honest premise

Real-time carrier API quotes are impossible from code alone: no public
carrier quote APIs exist, and selling/fulfilling real policies requires
producer licensing + carrier appointments (business work, not engineering).
The adapter interface stays frozen for that future. What ships today is the
real working model available now: **the user submits once; licensed local
agents receive a professional quote request and reply with REAL quotes.**
Lead-gen infrastructure, not simulation.

## What changed

### Backend — `POST /api/quote-requests` → 201
- **Body:** `{ jobId, agentIds[1..3], contact: { name, email, phone }, consent: true }`.
  Zod-validated: `jobId` must reference a **completed** quote job (404/422
  otherwise); `agentIds` must exist in the agent directory for the job's
  state/ZIP (re-looked-up server-side through the same provider chain the UI
  renders — 422 on unknown ids); `consent` must be **literally `true`**
  (TCPA — anything else is a 400).
- **Ref code** `QP-XXXXXX` (unambiguous alphabet, no 0/O/1/I/L).
- **Persistence:** new `quote_requests` table in the analytics SQLite store
  (gitignored; `:memory:` in tests). Contact is stored (the consented purpose
  is forwarding it to agents) but **never logged** — logs carry ref code +
  truncated phone hash only. Postgres migration for this table is future work.
- **Delivery provider chain per agent:**
  1. Agent record carries a **verified email** → professional request email via
     the email service (subject `New quote request QP-XXXXXX — N driver(s), M
     vehicle(s), ZIP`; body: structured profile summary with **age bands, not
     exact ages**, vehicles, coverage, contact + reply-to; QuotePilot
     identified as a comparison service, not a producer). → `emailed`.
  2. Otherwise → **`handoff`**: no fake email is sent. The response carries a
     tap-to-call card (phone/address) so the user reaches the agency directly.
- **User receipt** email (dev-log until SMTP configured): ref code, per-agent
  status, honest expectations ("real quotes from licensed agents — not
  estimates").
- **Profile summary is built server-side from the stored job** (new
  `JobQueue.getJobRequest`) — the client is never trusted to describe the profile.
- **Rate limit:** 5/hour per IP (contact vector). New `quoteRequestLimiter`.
- **Analytics:** `quote_request_submitted` with delivery mix only — no PII.
- `emailService` refactored around a shared `sendMail` core (SMTP/dev-log,
  domain-only logging); `sendQuotesReady` behavior unchanged.
- `routes/agents.ts` refactored onto the new `services/agentDirectory.ts`
  (same behavior, same logs); the quote-request flow reuses it for validation.

### Frontend — "Get real quotes" on the results page
- New section under the agents list: **"Want real numbers? These licensed
  agents will quote you for real."** Checkbox cards (max 3, accessible
  fieldset/legend) → review panel → confirmation.
- Review panel: contact prefilled **read-only** from the wizard's localStorage
  draft ("Edit in wizard →" link); manual entry fallback if the draft is gone
  (never a dead end). TCPA checkbox **unchecked by default** with the exact
  consent language ("Consent is not a condition of using QuotePilot").
- Confirmation: big `QP-XXXXXX` ref code, per-agent status ("Request emailed
  to X" / "Call X at {phone} — mention ref {code}" with tap-to-call), honest
  expectations copy, and a **"Copy my details"** button (plain-text summary for
  pasting into an agent's contact form).
- Copy rule enforced throughout: **the agents quote, never QuotePilot.**
- Also fixed three broken `Link to=` leftovers (react-router) in Quotes.tsx.

### Shared types
- `QuoteRequestContact/Delivery/HandoffCard`, `CreateQuoteRequestInput`,
  `CreateQuoteRequestResponse`, `QuoteRequestRecord`, `QuoteRequestDeliveryMethod`.

## The data-gap note (for the owner)

- **Today, every delivery is `handoff`.** Neither Google Places nor the sample
  seeds carry agent email addresses, so the `emailed` path is wired, tested
  (mocked), and waiting — but not live. The chain is honest: it never pretends
  to have emailed anyone.
- **How `emailed` goes live:** an agent claim/portal flow where agencies verify
  and register a contact email (future work), or a curated agency directory
  with known emails. Until then, the tap-to-call handoff IS the real product —
  and it's genuinely useful: one tap, ref code in hand, real conversation.
- **No new env vars.** `SMTP_*` now actually sends these emails when configured
  (agent requests + user receipts), in addition to the quotes-ready mails.

  unaffected (no route changes).
- **API suite: 148/148 pass** (138 before + 10 new `quoteRequests.test.ts`):
  consent=false/missing rejected, >3/0 agents rejected, unknown job 404,
  unknown agent 422, handoff delivery + user receipt, emailed delivery with
  verified agent email (mocked directory + transport; body asserts age bands,
  no exact ages), no raw phone/email/name in any log line, 5/hour rate limit

  `ipKeyGenerator("::ffff:127.0.0.1", 56)`.
- **Live smoke** (dev server, sample MA profile): job → complete (6 results)
  → agents (8, geocoded) → `POST /api/quote-requests` → **201**,
  `refCode QP-E4SN54`, 2× handoff cards with phones/addresses; dev-log shows
  `email_would_be_sent` (receipt, domain only), `quote_request_saved` /
  `quote_request_submitted` (ref code + phone hash, no PII); PII leak scan of
  the log: **0 hits**; record persisted in `quote_requests`.

## Deferred (with reasons)

- **Agent email capture** (claim/portal flow): the unlock for the `emailed`
  path. Product + trust work, not just code.
- **Agent-side status** (did the agency respond?): needs the portal above.
- **Postgres migration** for `quote_requests`: follows the analytics-sink
  pattern when operational.
- **Deduplication** (same user → same agency twice): ref codes make repeats
  visible; server-side dedupe is a fast follow if spam becomes an issue.
