# QuotePilot v0.10.0 "Next.js" — release notes

**Date:** 2026-10-08
**Type:** platform migration (no redesign, no feature changes)

The frontend moved from a Vite SPA (React Router + react-helmet-async) to
**Next.js 14.2 (App Router) with React 18** — full SSR for static content,
server-rendered metadata on every route, and Vercel-native deployment.

## What changed per route

| Route | File | Rendering | Notes |
|---|---|---|---|
| `/` | `src/app/page.tsx` → `src/views/Home.tsx` | Server shell + client view | Title/meta/OG/canonical + FAQ JSON-LD are SSR; hero form, marquee, FAQ accordion stay interactive |
| `/quote` | `src/app/quote/page.tsx` → `src/views/Wizard.tsx` | Client | 5-step wizard, localStorage resume, validation — unchanged behavior |
| `/quotes/[jobId]` | `src/app/quotes/[jobId]/page.tsx` → `src/views/Quotes.tsx` | Client (dynamic) | Polling, progress, compare, email opt-in; metadata title uses the "gathering" variant (client flips it on completion as before) |
| `/agents` | `src/app/agents/page.tsx` → `src/views/Agents.tsx` | Client | Leaflet via `next/dynamic(ssr:false)`; Suspense boundary required by `useSearchParams`; deep-link `?zip=&state=` preserved |
| `/about` | `src/app/about/page.tsx` → `src/views/About.tsx` | **Server** | Fully prerendered HTML; the one tracked CTA is a client `<TrackedCta/>` island |
| `/terms`, `/privacy`, `/disclosures` | `src/app/*/page.tsx` → `src/views/*.tsx` | **Server** | Fully prerendered HTML |
| `*` | `src/app/not-found.tsx` | Server | Replaces the react-router catch-all |

## Client/server split

**Server components:** root layout shell, metadata/JSON-LD, About/Terms/Privacy/Disclosures
content, not-found page.
**Client components (`"use client"`):** Header, Footer, RouteTracker (page-view analytics +
focus management), ThemeProvider, CookieBanner, Home, Wizard, Quotes, Agents, AgentMap,
Reveal, Select, LoadingMessages, StateDisclosurePanel, QuoteDisclaimer, TrackedCta.

**Intentionally client-rendered (with reasons):**
- Home — the ZIP hero form, carrier marquee fetch, and FAQ accordion are inherently
  interactive; only the SEO shell (title/meta/OG/JSON-LD) is server-rendered.
- Wizard / Quotes / Agents — localStorage, polling, and Leaflet all require the browser.
  Server-rendering them would add complexity for zero crawlable content (nothing indexable
  lives behind a form or a job id).

## Deleted / replaced

- `vite.config.ts`, `index.html`, `src/main.tsx`, `src/App.tsx`,
  `src/components/Seo.tsx` (replaced by the metadata API via `src/lib/metadata.ts`),
  `src/components/Layout.tsx` (split into `Header`/`Footer`/`RouteTracker`),
  `src/vite-env.d.ts` → `next-env.d.ts`, `src/pages/*` → `src/views/*`
  (Next.js reserves `src/pages/` for the legacy Pages Router).
- Uninstalled: `vite`, `@vitejs/plugin-react`, `react-router-dom`, `react-helmet-async`.
- Added: `next@14.2` (React 18 kept — no React 19 upgrade), `@types/node`.

## Environment variables

| Variable | Purpose | Default |
|---|---|---|
| `NEXT_PUBLIC_API_URL` | Deployed API origin in production (replaces `VITE_API_URL`) | empty = dev `/api` rewrite |
| `API_PROXY_TARGET` | (dev only) where `next.config.mjs` proxies `/api/*` | `http://localhost:3001` |

`NEXT_PUBLIC_API_URL` is the only new required variable for production deploys.

## Running dev

Unchanged: `scripts/dev.sh` still boots API (:3001) + web (:5173) + dashboard (:5174).
The web `dev` script is now `next dev -p 5173`; `/api/*` is proxied to the local API by
`next.config.mjs` rewrites, so no code changes were needed for local development.

## Vercel deploy notes

- `apps/web/vercel.json` is now minimal: `"framework": "nextjs"` + the existing security
  headers. No `buildCommand`/`outputDirectory`/SPA rewrites — the Next.js preset handles it.
- Set `NEXT_PUBLIC_API_URL` to the deployed API origin (e.g. Render) in the Vercel project.
- `next build` prerenders 8 routes statically; `/quotes/[jobId]` is dynamic
  (server-rendered on demand). Verified in build output.

- Analytics: `fireAnalytics` now uses the shared `API_BASE` so events hit the right origin
  in production (previously hardcoded to relative `/api/...`).

## Known deltas from the Vite build

- The Quotes page `<title>` no longer flips to "Your quotes are ready" in the static
  metadata — the client still updates `document.title` on completion as before; only the
  SSR default is the "gathering" title.
- Home's JSON-LD uses the generic carriers FAQ answer at SSR time (the client
  enhances the visible FAQ with live registry names, as before).
